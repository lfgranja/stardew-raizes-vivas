## Problem

The mod can build (`dotnet build` passes) and pass internal tests (1447 passed / 0 failed on `dev` @ `0e7b468`), but `In-game runs: 0`. The Phase 2 growth hook (`ApplySoilGrowthModifier()`) reads real soil health data but has never been confirmed to change `Crop.newDay()` behavior in a live SMAPI session. The verification gap blocks `verified` status (Constitution v2.0.0 Gate 3) and prevents confident merge of 19 remaining roadmap features (`ROADMAP.md`).

### FR-002 — Phase 2 Hook Integration Verified (Scripted Session, Clarified 2026-10-25 — COMPLETA)
- **FR-002a** (superseded in part by Round 3 decision): The growth modifier activates during `DayEnding` (moved from `DayStarted` per Round 3 decision, to avoid composition with vanilla `Crop.newDay` which runs in `newDayAfterFade` after `DayEnding`) — **not** `DayStarted`/`DryStarted`. It reads `SoilHealthService.GetSoilHealth()` for farm tiles (all farm locations, not only `currentLocation`), applies the tier multiplier to a cached base `phaseDays` (Pobre 1.15×, Moderado 1.00×, Saudável 0.85×), and the scripted session must capture event firing in the SMAPI log. Host-guarded and idempotent (Round 3).

  **Additional requirements (Clarify 2026-10-25, resolved autonomously from codebase + research):**
  - **Host guard:** `if (!Context.IsMainPlayer) return;` at top of `OnDayEnding`, before any processing. Farmhands must not execute. Single-player is degenerate case.
  - **Idempotency:** Key `season:dayOfMonth:year` per location, serialized as the exact string `$"{season}:{dayOfMonth}:{year}"` with `season = ISeasonProvider.CurrentSeason.ToLowerInvariant()`, `dayOfMonth = Game1.dayOfMonth`, `year = Game1.year`, formatted with `CultureInfo.InvariantCulture` (ordinal comparison). Storage MUST reuse the established `SoilDecayService` pattern: `Dictionary<string, string>` keyed by `locationName`, guarded by a lock, record-before-work, trace log on skip ("idempotent skip" including the key). Do NOT introduce a parallel `_soilGrowthProcessedLocations`/`_soilGrowthLastDayKey` scaffold that diverges from this pattern. On re-fire (save/load): skip + log at `LogLevel.Trace`. No reprocessing, no side effects.
- **Base `phaseDays` cache:** Do NOT hold a `Dictionary<object,int[]>` keyed by `Crop` instance. Instead restore the base via vanilla `Crop.ResetPhaseDays()` (restore from `CropData`) **before** applying the tier multiplier. This makes idempotent reapplication self-correcting, avoids orphaned instance-keyed caches across save/reload, and prevents save pollution. Multiplier applied after restore: Pobre 1.15×, Moderado 1.00×, Saudável 0.85×; never below 1; never touch the 99999 sentinel.
  - **Location scope:** `ApplySoilGrowthModifier(string locationName)` via `ILocationProvider.GetLocationByName`; called in `foreach (var locationName in farmLocationNames)` in `OnDayEnding`. Locations: at minimum `Farm`, `Greenhouse`, `currentLocation`.
  - **Exception handling:** Missing location (null) → skip, log at `LogLevel.Trace`. Null `SoilHealthService` → skip, log at `LogLevel.Trace`. NaN health tiles → **skip (no change; do NOT normalize to 0)** — NaN means "unknown/unmeasured" (`HealthCategory.Unknown`), not Poor; penalizing unmeasured tiles with 1.15× slower growth would be a false negative. Reserve NaN→0 normalization for arithmetic baselines only (`CompostApplicationService`, `SoilDecayService`), where 0 = "no health yet" is semantically valid. Zero/missing health (sparse cache → 0) → skip (vanilla; do NOT treat as Poor tier). Empty location → no-op, no logging. (Current code already skips NaN naturally, since both `health < 34` and `health >= 67` are false for NaN; no implementation change required — documentation only.)
  - **DayStarted scope:** `DayStarted` subscription remains for composting bins and soil decay (`ProcessDayStart`). Only `ApplySoilGrowthModifier()` call moves to `DayEnding`. Subscription NOT removed.
  - **Multiplayer messaging:** Host-only computation on farm-scoped `Crop.phaseDays`. No `SendMessage`/`ModMessageReceived` required (would create redundant transport, violating Principle VI). Propagates via vanilla location sync.
  - **Performance:** Three-tier contract: (1) production code measures entry→return with `Stopwatch` and logs elapsed ms at `LogLevel.Trace` only (never a hard runtime failure; game must stay responsive); (2) unit tests (`GrowthPerformanceTests`) keep scaling/linearity + coarse ceiling (no wall-clock ≤5 ms assertion — host-dependent and flaky); (3) scripted pipeline / SC-009 criterion 6 parses the trace line and hard-fails if elapsed > 5 ms for that run. Scan target: up to 40,000 tilled tiles across all farm locations. Chunking (≈1,000 tiles/chunk, prime-modulus stride) activates only above 5 ms; activation is a measured, logged decision verified via `GetChunkStartIndices` correctness tests plus an optional injected 40,001-tile synthetic-location test.

## Multiplayer Verification (Constitution VI)

**Host-mediated messaging:** NOT required for the growth modifier. Growth modifier is host-only computation on farm-scoped `Crop.phaseDays`. No `SendMessage`/`ModMessageReceived` needed (would create redundant transport, violating Principle VI "no second source of truth"). Host's mutation propagates through vanilla location sync. Explicitly documented as a negative requirement.

**Multiplayer "verified" criteria (M1–M7):**
| # | Criterion | Verification Method | Scope |
|---|-----------|-------------------|-------|
| M1 | Host-authoritative design | Design doc shows no divergent player-count branch | Mechanism (stub-bounded) |
| M2 | Structural scan | No code path where farmhand input changes shared farm state | Mechanism (stub-bounded) |
| M3 | First-wins semantics | `HostAtomicLockService` used for shared-state mutations | Mechanism (stub-bounded) |
| M4 | Farm-scoped parity | Save data keyed by farm, not player | Mechanism (stub-bounded) |
| M5 | Host guard reality | Live session: farmhand does not execute growth modifier | Requires live session |
| M6 | Idempotency on save/load | Save/load re-fire test: modifier does not double-apply | Requires live session |
| M7 | Scope-label discipline | Claims use `verified (host-only)` not `live 2-player verified` | Documentation |

`verified (host-only)` = M1–M4 satisfied (mechanism). `live 2-player verified` = M1–M7 satisfied. These are distinct labels.

**D1 (live 2-player) re-entry criteria:** D1 does not block `verified`. Re-entry triggers only when: (1) a feature uses a `SendMessage`/`ModMessageReceived` transport path, or (2) ROADMAP explicitly schedules D1. Gates: GamePath available → single-player `verified` achieved → documented 2-instance procedure → evidence capture plan. Not triggered per-feature.

**Multiplayer edge cases:**
- **Farmhand join/leave during DayEnding:** No special handling needed. Growth modifier is host-only, single execution per DayEnding. Idempotency key prevents reprocessing if event re-fires. Farmhand join mid-execution does not affect host's computation.
- **Concurrent execution:** First-wins semantics via `HostAtomicLockService` (existing pattern). Growth modifier processes tiles sequentially within the host's DayEnding handler; no concurrent access to shared state from farmhands.
- **Host disconnect/reconnect:** Host session ends on disconnect. On reconnect/reload, idempotency key (`season:dayOfMonth:year`) prevents double-apply. Farmhands cannot save or mutate shared state.
- **Multiplayer save/load:** Host owns the save. Farmhands join via sync and never load independently. Farm-scoped persistence via `IDataHelper` keyed by `ISaveIdProvider` farm key. `PerScreen<T>` is UI-only, not farm state.
- **Split-screen peers:** Distinct players by `UniqueMultiplayerID`. Same host-authority rules apply.
