## Summary

Add the already-established fail-fast credential diagnostic to the single CI job that lacks it, enforce the invariant with a deterministic workflow-contract test, and document the local-versus-hosted CI trust boundary. No runnable game code, save data, or locale strings change.

**Target Platform**: GitHub Actions (`.github/workflows/*.yml`) on `ubuntu-latest`; local validation on this Linux host.

**Project Type**: CI configuration + deterministic tests (no application source changes).

**Performance Goals**: N/A — the guard is a pre-flight check; no measurable runtime budget applies.

**Constraints**: fail closed (absent/empty credential is a FAILURE, never skipped or green); do not modify branch protection, secrets, auto-merge, tags, releases, `verify-scenario.yml` warning path, or `release.yml`; no runnable C#; paths must stay disjoint from the owner's unpushed local docs commits.

**Scale/Scope**: 5 workflows inspected, 3 non-best-effort credential consumers (2 already guarded), 1 new test module, 1 documentation section.
