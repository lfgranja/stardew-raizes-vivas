## Research Notes

- **SMAPI Android support**: community port (NRTnarathip, v4.3.2.x, April 2026), lagging behind official SMAPI (4.5.2). Explicitly experimental: "some mods don't work yet." Cinderbox (Ekyso) runs desktop PC build on Android via custom SMAPI fork (separate ecosystem).
- **Harmony rewriting limitations**: SMAPI rewrites mods' compiled IL for cross-platform differences and breaking changes, but cannot rewrite Harmony annotations (`[HarmonyPatch]` + `PatchAll`). Mods using code API are more rewriteable but still not guaranteed.
- **Android backend**: MonoMod.RuntimeDetour (via HarmonyDetourBridge), not Harmony's native ASM jumps (ARM devices require it).
- **Recommended posture**: declare untested (README, Nexus page, don't tick "Android Compatible" tag); optional runtime guard; best-effort fallback to vanilla on patch failure. Never claim support without testing.
- **Project posture**: no platform checks in code (delegate to SMAPI/MonoGame); desktop-only per GDD ("Sem console/mobile no v1"); no Android TFM or RuntimeIdentifier; Gate 3 requires real SMAPI session with 3 signals (no Android harness).
- **Consistency**: accepting "untested on Android" is consistent with existing policy, provided the patch follows SMAPI's rewritable shape (code API, static, try/catch + fallback, postfix preferred, no transpilers).
