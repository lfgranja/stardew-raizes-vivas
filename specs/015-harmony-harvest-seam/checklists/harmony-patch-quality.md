## Research Notes

- **SMAPI Harmony guide** (stardewvalleywiki.com, Wayback 2025-11-18; biligame.com 2025-12-22): Harmony is a last resort; code API (not annotations/`PatchAll`); prefer postfix over prefix; avoid transpilers; static methods; try/catch with fallback to original; `EnableHarmony=true` (SMAPI-bundled 2.2.x); warns of stability on Android/future updates.
- **Skill `stardew-valley-smapi` (cylixlee)**: confirms Harmony policy, code API, EnableHarmony, cross-platform defaults.
- **Skill `harmony-patching-mastery` (meyverick)**: mandates static methods, prefer postfixes, transpilers last resort, try/catch with fallback, idempotency/isolation.
- **aedenthorn `StardewValleyMods`**: `Crop Quality` and `Crop Variation` patch `Crop.harvest` via Harmony transpiler on 1.6.15 — proves mechanism is routine.
- **T007 spike**: `Crop.harvest` is `public virtual bool harvest(int, int, HoeDirt, JunimoHarvester, bool)`; `Object.Quality` get/set; `HoeDirt.dayUpdate`; `Crop.dayOfCurrentPhase`/`newDay`/`phaseDays` confirmed. Public-field path insufficient → Harmony required.
- **internal-patchstyle.md**: non-suppressing two-phase patch (Prefix returns true + Postfix); suppressing prefix never acceptable; quality is a local (postfix can't modify in-method roll; seam decides final quality, patch applies post-hoc).
- **research-patchstyle.md**: recommends Postfix (with non-skipping Prefix for state capture); Transpiler as documented fallback; avoid Prefix-returning-false. Caveat: `__result` is bool success flag, not the item; pure Postfix can't modify the local roll.
- **internal-seam.md**: recommended seam interface (`IHarvestQualityService` with `Decide`/`ResolveFeedback`/`BoostQualityProbability`/`BoostExtraHarvestChance`); types `HarvestTier`/`HarvestFeedbackFlags`/`HarvestQualityInputs`/`HarvestQualityDecision`; pure, stateless, testable.
- **research-seam.md**: Feathers seams, Humble Object, DI, xUnit/FsCheck property-based + state-machine testing; Pathoschild Tests.Common pattern.
- **internal-android.md / research-android.md**: no platform checks in code; desktop-only policy; Android = community port (experimental); Harmony rewriting can't rewrite annotations; accept "untested on Android" with documentation; best-effort fallback to vanilla.
- **Constitution v2.0.0**: Principle I (DDD), II (Security), III (Async), IV (TDD), V (YAGNI — Harmony only when necessary), VI (Multiplayer first-class).
- **spec 014**: FR-001–FR-016, SC-001–SC-010, A6 (crop scope), A7 (sparse-cache 0), A8 (replicated deterministic roll), B1/B2 (feedback conditionality/co-occurrence), Q2 (hook names), Q4 (CollectCompost fix), Q6 (numerical balance), Q7 (pest scope), Q9 (no persistent marker), Q10 (Gate 3).
