## Research Notes

- Vanilla `Crop.harvest`: main item goes through `Farmer.addItemToInventoryBool`; on failure shows red "Inventory full." message and `success` stays false (crop stays in ground). No debris for main item. (research-c1, decompiled 1.6.15)
- Extra-harvest items (`ExtraHarvestChance` / multi-yield) are **always** dropped as ground debris (`numToHarvest - 1` items via `createItemDebris`), regardless of inventory; auto-collect on pickup if space, else stay on ground. Not lost. (research-c1)
- Giant crops always drop as debris; inventory never blocks. (research-c1)
- Mod best practice: never silently destroy; use `addItemToInventoryBool` + red message for guaranteed first unit; spawn overflow/bonus as debris. Prefer `couldInventoryAcceptThisItem` for vanilla red message. Batch mods skip when first unit can't fit. (research-c1)
- NaN is the absence-of-measurement sentinel (distinct from measured 0); codebase consistently treats NaN/Inf as Unknown (gray overlay, skip in growth modifier, no-op in decay). (internal-c3)
- Measured 0 (sparse-cache floor) → Poor → force 0 (intentional, "may need tuning"). (Spec Edge Cases)
- Finite out-of-range → clamp to boundary category (below 0 → Poor; above 100 → Healthy). (internal-c3)
- Edge-case audit (chk-edgecases) identifies 10 actionable amendments (R1–R10) including: inventory-full contract, NaN handling, debris drop specification, persistence failure modes, multiplayer divergence.
- Uncertainty register: red-message wording (inferred), debris despawn timer (unverified), mod-specific behavior (no authoritative sources). (research-c1)
